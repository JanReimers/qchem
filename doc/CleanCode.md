## ANCHOR-MOVING BATCH — one sprint, re-bank once (user 2026-10-03)

Rows whose fix can MOVE a banked number (or a convergence trajectory an anchor depends on).  They are deliberately
NOT worked one at a time: each would force a re-bank of its own, and a delta is only attributable if exactly one
thing changed.  **Do them in ONE window**: take a full `ctest -j8` + `-L long` baseline, land the changes ONE AT A
TIME in the order below with a sweep after each (so every anchor delta has a named cause), then re-bank the moved
anchors together.  `doc/Pins.md` pin 10 applies: an energy anchor that moves is RE-JUDGED against an independent
route (CP2K/QE/ABINIT oracle, `doc/Benchmark.md`), never refreshed.  A failing charge / count / weight sum is
physics and cannot go stale.  Also in the batch but tracked in `doc/OpenWork.md` §3: **N4** (cusp-deficit XC feed,
pin 18).  Suggested order (cheapest to attribute first): D-MINDRHO → V1.24(iii) → D5 → V1.22 → D12 → §K.
